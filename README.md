# 重みの直接解析・編集による、より適した手法の探索（Qwen3.5-0.8B）

## ゴール
**研究として、重みを直接解析し、編集するための「より適した手法」を考案し、検証すること。** 対象は、Qwen3.5-0.8B の数学（思考モード、上限 16,384 トークン）の正解率です。

ブログ「Sparks of Weight-Space Programming」（https://rikiyat.github.io/blog/weight-space-programming/）の実験8で報告された編集は、比較の**基準**です。これを再現して基準を作り、そのうえで次を比べます。

- 対象を見つける情報源: 重みだけ ／ 少数の活性 ／ 正解率のフィードバック ／ ラベルなしの信号
- 編集の形: ランク1の射影、層ごとの強さ、列の選び方、注意ヘッド
- 選び方・最適化: 閉形式、ブラックボックス探索、AdamW による方策勾配、ラベルなしの選択
- 探索の効率: 安い情報で優先順位をつけ、高価な評価（正解率の全評価）は少数にだけ使う（段階的半減など。Issue #25）

「より適している」の基準と、候補手法の一覧は、Issue #24（研究の方針）にあります。

## これまでの検証の内容
1. 公開された編集の効果を再現できるか
2. 自前の手順で、同様の編集を作れるか
3. 正解率を目的関数にした最適化（ブラックボックス探索、AdamW による方策勾配）で、どこまで上がるか

## 立場と範囲
- **非公式の第三者による検証**です。ブログの著者とは関係ありません。
- 作業は AI（Claude Code）が行い、方針は依頼者が決めています。ブログの編集を行ったのは GPT-6 Astra で、モデルが異なるため、「LLM が重みを読んで編集を作る過程」の再現は対象外です。確かめているのは、編集の効果と、明示的な最適化でどこまで上がるかです。
- 元のログ（https://github.com/RikiyaT/lm_understand-logs）は、このリポジトリに含めていません。`scripts/apply_published_edit.py` は、その編集ロジックを独自に再実装したものです。
- 各結論には、事実と推定を分けて書いています。

## 管理の方法
- 検証項目ごとに **Issue** を立て、結果をコメントに付けて、完了したらクローズします。
- 変更は PR を使わず、`main` に直接コミットします。

## 現在わかっていること（16,384 トークン上限、設定選択用 128 問）
| 編集 | 正解率 |
|---|---|
| 基底 | 13.3%（1回/問） |
| 公開編集 | 46.1%（1回/問） |
| 自前の編集（旧方向、層15+19、k=64、α=6） | 41.4%（1回/問） |
| 自前の編集（同、α=12） | 35.2%（1回/問） |
| 新しい方向、層15+19 | 38.3%（2回/問） |
| 同、層10+14 | 25.8%（2回/問） |

8,192 トークン上限では、編集の効果が隠れます。比較は 16,384 トークンで行っています。進行中の項目は Issue を参照してください。

## 構成
| 場所 | 内容 |
|---|---|
| `scripts/` | 評価（`eval_math.py`）、編集の作成（`make_edit.py`）、探索（`bo_search.py`）、分析、キュー用のシェル |
| `reports/` | 報告（`report.md`、`report.html`）、計画、分析メモ |
| `data/` | 検証に使った問題の部分集合（GSM8K と MATH-500 から抽出） |
| `results/` | 各評価の要約（`summary.json`）と標本（`samples.jsonl.gz`） |
| `docker/` | vLLM を動かすイメージの定義 |

## 含まないもの
モデルの重み、元ブログのログ、第三者のデータ（GSM8K 全体、MATH-500 全体、DecisionBench）、生ログ。必要な場合は、各配布元から取得してください（`scripts/prepare_data.py` が問題の準備を行います）。
