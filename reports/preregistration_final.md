## 7. 統計手法（固定）
- 実装: `scripts/final_analysis.py`（sha256 は §12 で記録）。保存済みの `samples.jsonl.gz` だけを使う。
- 推定量: 全標本の正解数 / 全標本数。問題ごとの標本数が違う場合は、標本数で重みがつく。この最終確認は 1 回/問なので、問題あたりの正解率の平均に一致する。
- 不確かさ: **問題単位のクラスタ・ブートストラップ**。問題を復元抽出し、各問題の標本は一緒に動かす。反復 10,000 回、シード 20261104（固定）。同じ再標本化をすべての候補に使うので、基底との差は対応ありになる。
- 区間: 95% パーセンタイル区間（補正しない）。
- p 値: 両側。`p = 2 × (min(#{d* ≤ 0}, #{d* ≥ 0}) + 1) / (10,000 + 1)`（d* = 再標本化した差）。最小値は約 0.0002。差が正確に 0 のときは 1。
- 多重性: Holm 補正（族1 の p 値だけ、族2 の p 値だけでそれぞれ）。
- 参考として、差を 0 に中心化した帰無分布による p 値も出力するが、判断には使わない。
- 実行コマンド（雛形。tag は §2 の表に従う）:

```
python -I scripts/final_analysis.py --base ff16k_base \
  --cands ff16k_p50c ff16k_own_a6 ff16k_mp_L15_19 ff16k_B ff16k_A ff16k_null \
  --set final_fresh --expect-n 256 --boot 10000 --seed 20261104 \
  --secondary ff16k_A:ff16k_B --out results/final_analysis/final_fresh
```

- スクリプトは、合成データの単体テスト（ブートストラップの被覆率、Holm の手計算との一致）と、選択用 128 問の既存結果での試運転で確認済み（`results/analysis_test/`）。最終確認の評価の前に、同じテストをもう一度実行して全項目が通ることを確認する。

## 10. 除外規則
- 標本の除外はしない。採点で不正解になった標本、打ち切られた標本、答えを出さなかった標本も、すべて分母に入れる。
- 問題の除外は、評価の前の整合性確認（§3）だけで行う。除外する場合は、全候補共通で除外し、問題数と ID を記録する。評価の後に、結果を見て問題を除外しない。
- 異常終了（プロセスの異常終了、メモリ不足、コンテナの停止、標本数が 256 でない、`finish` が `stop` と `length` 以外の標本がある）の候補は、部分結果を使わず、その候補を最初からやり直す。やり直しは同じ設定・同じシードで行い、回数を報告する。
- 異常終了以外の理由（結果が期待と違う、など）で再評価しない。各候補の評価は 1 回だけ。

## 13. 既知の限界（登録時に認めておく）
- 256 問 × 1 回/問では、小さな差（数ポイント）は検出できない。+10 ポイントを 80% の検出力で見つけるには、256 問程度が必要という見積もりに基づく（`plan_v2_after_review.md` §1 #11）。
- 同じ重みでも、GPU・vLLM の非決定性で、再実行すると標本が変わる。1 回/問の結果は、サンプリングの揺れを含む（ブートストラップは問題の揺れを扱うが、同じ問題での標本の揺れは分けて推定しない）。
- 採点の `grade.extract` は、思考が閉じていないとき、本文全体の最後の `\boxed{}` を使う。このため、思考が閉じていないまま（finish=length のまま）正解になる標本があり、予算別の正解率の 16,384 の値が、主指標より小さくなることがある。件数は報告に書く。
- 方法B・方法A・ヌル対照は、設定選択用のデータで選んだものであり、最終確認でも勝者の呪いが完全に消えるわけではない（選択に使っていない問題で測るので、偏りは除かれるが、候補の数だけ比較が増える）。
- 繰り返しの周期（`find_loop`）は、再トークン化した本文に基づく近似であり、元の出力トークン列と完全には一致しない場合がある。
- 編集の設計と実行は Claude（LLM）が行った。元ブログの「LLM が重みを読んで編集を作る過程」の再現ではない（`plan_v3_current.md` §5）。
