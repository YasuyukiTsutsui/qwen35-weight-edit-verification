## 5. 主解析（固定）
- 実装: `scripts/final_analysis2.py`（sha256 は §9）。保存済みの `samples.jsonl.gz` だけを使う。
- 推定量: **0.5 × GSM8K の正答率 + 0.5 × MATH の正答率**（層別の固定重み。各層の正答率は、正解の標本数 / 標本数）。MATH と GSM8K で効果の大きさも向きも違うため、混ぜる比率を固定する。単純な全体平均は、記述としてだけ併記する。
- 不確かさ: **層別・問題単位のクラスタ・ブートストラップ**（各層の中で問題を復元抽出し、問題の標本は一緒に動かす。同じ再標本化を全候補に使うので、差は対応あり）。反復 10,000 回、シード 20261105。95% パーセンタイル区間。
- **主比較は 1 本**（追補で、候補 − 基準編集、と書く）。両側。p 値 = 2 × (min(#{d* ≤ 0}, #{d* ≥ 0}) + 1) / (10,000 + 1)。1 本だけなので、多重性の補正は要らない。
- 副比較・基底との差・層別・ブロック別・予算別（4,096／8,192）・打ち切りの内訳は、すべて**探索的・記述的**とし、そう明記する。副比較を複数置くときは、その族の中だけで Holm 補正する。
- 判定ルール（追補で、候補と基準編集の対に当てはめる）:
  - 主比較の区間の下限が 0 を超える → 「この条件で、候補は基準編集より良い」と報告し、候補を新しい基準編集にする。
  - 区間が 0 を含む → 「区別できない」と報告する（同等であるとは言わない）。
  - 区間の上限が 0 を下回る → 「基準編集より悪い」と報告する。
- **非劣性**（「同等の水準に届く」と主張したいときだけ）: 追補に、余白 M を、結果を見る前に書く。主比較の 95% 区間の下限が −M を超えれば成立。M は、想定する区間の半幅（§7 の表）より小さくしない（検出力が足りなくなるため）。
- 層別の結果（GSM8K、MATH）を、必ず併記する。前回は、方法B と公開編集の差が GSM8K で −0.8 pt、MATH で +4.7 pt と、層で違った。
- 実行コマンドの雛形: `python -I scripts/final_analysis2.py --runs <候補> <基準編集> ... --blocks C1 --primary <候補>:<基準編集> [--noninf-margin M] [--base <基底>] --out results/final2_analysis/<名前>`

## 6. 候補の入場規則と、候補の選び方の開示
追補に書く候補は、次を満たす。
1. 重みのファイルが固定され、sha256 が追補に書かれている。
2. 候補を選ぶまでに行った評価（設定の数、標本数、GPU 時間、使った問題セット）が、追補に書かれている。
3. 探索側（設定選択用 128 問、検証用 128 問）での見積もりが、基準編集に対して +4 pt 以上である（効率や非劣性の主張なら、その主張に対応する基準を、追補に書く）。
4. 前回の候補から外すものがあれば、その理由を結果を見る前に書く（例: 前回の自前 α6 と対比方向は、探索側の見積もりが基準に届かないため外す、など）。
