### 2.2 編集の式

元ブログの編集は、MLP の `down_proj` の重み行列 W（Qwen3.5-0.8B では 1024 × 3584。行は残差の座標、列は MLP のニューロン）の一部の列 S から、ある方向 u の成分を引く操作です。

```
W'[:, S] = W[:, S] − α · u (uᵀ W[:, S])
```

- u は単位ベクトルで、「繰り返しに入る方向」を表します（残差の 1024 次元の空間の方向。行について密です）。
- 列は MLP のニューロン1個分の出力側の重みです。S はその一部（上位 k 列）です。
- α = 1 は u 方向の成分を取り除く操作です。α > 1 は取り除いたうえで逆向きにも押す操作で、α = 2 で成分の符号が反転します。
- 編集の大きさは、行列の相対変化 ρ = ‖ΔW‖_F / ‖W‖_F で表します。

### 3.2 自前編集の作り方

Claude は元リポジトリの手順をそのまま使わず、次の手順で編集を作りました。

1. 方向探索用の 256 問（GSM8K 128 問と MATH 128 問）で、基底モデルに 16,384 トークンまで生成させました。
2. 打ち切られた応答の末尾 1,024 トークンのうち、繰り返しに入っている部分を「繰り返しの文脈」としました。同じ応答の 256〜1,280 トークン目と、正しく完了した応答の思考の中ほどを「進んでいる文脈」としました。
3. 層15と層19で、この 2 つの文脈の MLP 出力の平均の差を u としました（以下「旧方向」）。
4. 各ニューロンに、`(u · W[:, j]) × (繰り返しの文脈での平均活性 − 進んでいる文脈での平均活性)` という点数を付けました。点数の上位 k 列を編集対象にしました。
5. 層15と層19という選び方は、元ブログから借りました。のちに、層の選び方を 3.5 節で検証しました。

後に、繰り返しが初めて現れる位置とその反復の差から作る別の方向（以下「対比方向」）も作りました。層の比較（3.5 節）と、方向のデータ量の検証（3.7 節）では、こちらを使っています。

基底モデルの測定（方向探索用 256 問、16,384 トークン）: 正答率 11.7%（30/256）、打ち切り 88.3%、うち繰り返しで終わった応答 219 件、思考を閉じた割合 12.5%。

### 3.3 8,192 トークンの結果と、その訂正

最初の測定は、上限 8,192 トークンで行いました（設定選択用 128 問、1 回/問）。

| 設定 | 正答率 | 繰り返しで終わった応答 | 思考を閉じた割合 |
|---|---|---|---|
| 基底モデル | 10.9% | 84 | 10.2% |
| 自前 k=64, α=6 | 15.6% | 20 | 24.2% |
| 自前 k=64, α=12（当時の最良） | 25.0% | 26 | 56.2% |
| 公開編集 | 26.6% | 4 | 32.0% |

当時の結論は、「繰り返しで終わる応答は減るが、自前編集の正答率の上昇は有意と言えない」でした（GSM8K 64 問で p = 0.098）。選択に使っていない 64 問での比較では、MATH-500 の応答の約 95% が 8,192 トークンで打ち切られ、効果を判断できませんでした。

**訂正（事実）:** 上限を 16,384 トークンにすると、基底との差がはっきり出ます。同じ自前編集（旧方向、k=64、α=6）は、8,192 では 15.6% でしたが、16,384 では **41.4%** でした。α=12 は 35.2%で、8,192 で最良に見えた α=12 より、α=6 の方が高くなりました（選択用 128 問、1 回/問）。8,192 トークン上限は、思考を最後まで終えられない応答を打ち切り、編集の効果を隠していました。そのため、以降の比較はすべて 16,384 トークンで行いました。8,192 の旧結果の詳細は、リポジトリの履歴（`reports/report.md` の前の版）に残っています。

### 3.5 層 15・19 が残った理由

層の選び方は、元ブログから借りたものでした。「なぜ 15 と 19 が良いのか」を確かめるため、同じ方法（対比方向、64 列、層ごとの ρ=12%）で、ほかの層も試しました（`reports/notes_layer_choice.md`、Issue #14）。

| 編集 | 正答率（設定選択用 128 問、2 回/問） | 繰り返しで切れた割合 |
|---|---|---|
| 基底（1 回/問） | 13.3% | 84.4% |
| 層10 | 21.9% | 68.0% |
| 層14 | 20.3% | 66.0% |
| 層10+14 | 25.8% | 57.4% |
| **層15+19** | **38.3%** | **25.4%** |
| 層10+14、ρ=6% | 10.9% | （221/256 系列） |
| 層11 単独 | 10.9% | （220/256 系列） |
| 層10+14、ランダム直交方向（ρ=12%） | 12.9% | （216/256 系列） |

事実:
- 層15+19 は、層10+14 より +12.5 ポイント（95% 区間 +6.2〜+19.1）、層10 より +16.4、層14 より +18.0 高い。基底で解けていた問題を、層15+19 では 1 問も失っていない（層10+14 は 1 問）。
- 層10+14 は、強さを半分（6%）にすると基底並みに戻る。同じ層・同じ強さでランダム方向を入れると基底並み。したがって、層10+14 の効果は方向に依存しているが、層15+19 より弱い。
- 層10・14 の編集は、周期 31 トークン以上の長い繰り返しを減らす一方、周期 30 トークン以下の短い繰り返し（例: 同じ記号の連続）を増やす。層15+19 の編集は、すべての周期の繰り返しを減らす。
- 教師強制（正解の続きを与えたときの対数確率）の選択性は、層10 が最大（11.5。層15 は 1.2、層19 は 1.8）だったが、自由生成の正答率は層10 の方が低かった。教師強制の指標は、正答率の予測にならなかった。
- 公開編集が層15・19 を選んだ理由は、元ログの調査（`reports/notes_astra_logs.md`）によると、手書きの 4 組の対比方向への各層の寄与の分解で、MLP の寄与が最大の 2 層が層15（0.2634）と層19（0.2497）だったことでした。生成の正答率で比べたのは「層19 のみ」と「層15+19」だけで、他の層を生成で比べた記録はありません。

推定（確かめていないこと）:
- 層10・14 の編集は、長い繰り返しを壊す代わりに、別の短い繰り返しに逃がしている。
- 層の種類（層3, 7, 11, 15, 19, 23 が全注意層。ほかは線形注意の Gated DeltaNet）が効いている可能性がある。ただし、全注意層の層11 を単独で 12% で試した結果は基底並みで、「全注意層だから効く」は支持されなかった。層の種類と深さは分離できていない。

限界: 層10・14 は強さ 12% と 6% の 2 点だけ、層11 は 1 点だけです。層15+19 が最良という結論は、この範囲での結論です。

### 3.6 編集の定数・対象を変えた検証（Issue #9）

中心の編集（層15+19、α=6、k=256、ρ は層15 が 15.98%、層19 が 17.46%）から 1 つずつ変えて、設定選択用 128 問 × 2 回で評価しました（中心の再評価は 43.0%）。

| 変えたもの | 正答率 |
|---|---|
| 層15 の強さ ×2 | 25.4%（上側に狭い崖） |
| 層19 の強さ ×0.5 / ×2 | 44.5% / 42.6%（平坦） |
| 層15 のみ | 43.8% |
| 層19 のみ | 15.2% |
| 層11 を追加 | 43.0% |
| 層23 を追加 | 0.4%（壊れる） |
| ランダムな 256 列（ρ を中心に合わせた） | 16.8% / 16.4%（2 シード） |
| 全 3,584 列（ρ を中心に合わせた） | 43.4% |

事実:
- 中心を上回る設定は見つからなかった。
- 効果は層15 にあり、層19 は繰り返しを減らす補助。層23 を足すと壊れる。
- 列は、**どの列を選ぶか**が効く。ランダムな列は、編集の大きさを合わせても基底近くのままだった。
- 一方、列の数を絞ること自体は正答率に要らない。全列に広げても同じ正答率だった。

推定: 「少数の列だけ」の意味は、正答率のためではなく、編集の差分を小さく（256 列だけ）保つことにあると考えられる。

### 3.7 方向のデータ量（Issue #13）

対比方向を作る繰り返しの標本数 n を変えました（層15+19、ρ=12%、k=64）。正答率は n = 4 / 16 / 64 で、23.8% / 31.6% / 38.3% と単調に上がりました。n=4 でも基底より高い（+10.5 ポイント、区間 [+4.3, +16.8]）。「少数のデータでも作れる」は、基底を超える意味では成り立ちますが、n=64 の水準には届きません。64 を超える本数は試していません。

### 3.8 重みだけで編集する場所を選べるか（Issue #23）

「データを使わず、重みの解析だけで編集する場所を選べるか」を、層15 の注意ヘッドで試しました（重みの OV 解析で上位に出たヘッドを除去・2 倍）。

| 編集 | 正答率 |
|---|---|
| ヘッド1 を除去 | 2.3% |
| ヘッド3 を 2 倍 | 0.0% |
| 両方 | 0.0% |
| 対照: 重みでは中立のヘッド7 を除去 | 19.1% |

事前に決めた成功基準は満たされませんでした。重みの順位と効果の順位は逆でした（重要なヘッドを壊すと、全体が崩れて繰り返す、と推定していますが、確かめていません）。この形の「重みだけ」の指標は、編集する場所の選択には使えませんでした。

### 3.9 探索による最適化: 方法B・ヌル対照・方法A

**方法B（ブラックボックス探索）**: α ∈ [2, 16] と k ∈ {64, 128, 256} の 2 変数を、ノイズを考慮した期待改善（EI）のベイズ最適化で探索しました（16 点 + 検証 3 点）。層は 15+19 に固定、方向は対比方向。

- 事実: 探索の最高値は α5.5・k256 の 46.5%（選択用）でした。探索が選んだのは α6・k256（選択用 46.1%、検証用 44.9%、再評価 43.0%）です。α4〜8・k256 の範囲は 40〜46% で平らでした。k=64 は α13 で 30.1%、k=128 は α2 で 22.7% など、広い範囲の外では下がります。
- 事実: 探索 1 回の費用は約 3.4 時間（GPU）です。

**ヌル対照**: 対比方向と同じノルムのランダムな直交方向を、同じ強さ（α6、k256、層15+19）で入れた編集 5 本は、選択用で 10.2〜19.1%でした。基底並みです。

**方法A（方策勾配 + AdamW、Issue #10）**: ランク1の編集 ΔW = −u vᵀ（v は上位 256 列）を、正答率を報酬とする RLOO の方策勾配と AdamW で学習しました（毎ステップ 12 問、8 ステップ、標本は初期の方策から生成、ρ ≤ 12%）。

|---|---|---|---|
| 方法A（学習後） | 43.0% | 44.5% | 12.0% |
| 方法A の初期値（k64、α5） | 37.5% | — | 約 10〜12% |

- 事実: u はほとんど動きませんでした（初期との類似度 0.998）。学習で変わったのは、列ごとの重みと強さです。
- 推定: 初期値より +5.5 ポイント上がった分は、強さを上げたことで説明できます（α6.5 の点との差は +1.2、区間は 0 を含む）。方法A が「方向を自力で見つけた」とは言えません。ランダムな初期方向からの学習と、密な v の対照は、実施していません。

### 3.10 ラベルなしの選択と、探索の効率（Issue #21・#25）

**ラベルなしの選択（#21）**: 正解ラベルを使わない指標で、編集の強さ・場所を選べるかを調べました。46 本の編集（選択用）での、全評価の正答率との Spearman 相関は次のとおりです。

| 指標 | 相関 |
|---|---|
| 完走して `\boxed{}` のある答えの割合 | **+0.98** |
| 同じ問題の 2 標本の答えが一致する割合 | +0.95 |
| 思考を閉じた割合 | +0.88 |
| 繰り返しで終わった割合 | −0.76 |

完走して boxed のある答えの割合で選ぶと、選ばれた編集は選択用で最高の正答率（46.5%、α5.5・k256）で、最良との差は 0 でした。思考を閉じた割合で選ぶと、閉じる割合は高いが正答率の低い編集（25.4%）を選び、誤りました。最終確認でも、この選択（ラベルなし選択）は 45.7% でした。

事実と注意: 完走して boxed のある答えの割合は、正解の部分集合を数えるため、正答率との相関には構造的な部分があります。正答率が 40% 以上の編集 15 本だけで見ると、相関は +0.68〜+0.70 に下がります。

**探索の効率（#25）**: 安い情報で絞り、高価な全評価は少数にだけ使う方式を、すでに評価した編集（18 本の未見のプール）で再現しました（CPU のみ）。

| 方式 | コスト | 最良との差 |
|---|---|---|
| 段階的半減 16→128 問 | 33.1% | 0.19 ポイント |
| ラベルなしの事前絞り込み（32 問、上位 4 本を全評価） | 40.9% | 0.10 ポイント |
| 一様な部分サンプル 16 問 | 12.5% | 1.21 ポイント |
| 上限 2,048 / 4,096 で絞る（順位相関 +0.27 / +0.33） | 38〜53% | 0.39 ポイント |

注意: このプールは「良い群」と「悪い群」にきれいに分かれ、良い群の中の差は標本ノイズの範囲（±1.5 ポイント）です。示されたのは「悪い編集を安く落とせる」ことで、「上位の中で最良を当てる」ことは確かめられていません。短い上限は順位相関が低く、危険です。

### 3.12 まとめ（事実と推定）

事実:
1. 公開編集の効果は、新しい問題でも再現した（13.3% → 46.1%）。
2. 効果は方向に依存する（ヌル対照は基底並み）。層は15+19の組、列は選び方が効き、数を絞ること自体は要らない。
3. 自動の手法（方法B、方法A、ラベルなし選択）は、公開編集と同じ水準に届いた。上回ったとは言えない。
4. 重みだけで場所を選ぶ試み（注意ヘッド、#23）は成功しなかった。
5. 安い情報で絞る方式は、このプールでは悪い編集を安く落とせた。
6. 方向 u が「少数の残差座標に集中している」ように見えたのは、座標 0（残差の外れ値チャンネル）1 個だけが原因だった。層19 の u² の 30.8% が座標 0 にあり、2〜16 位の合計（9.1%）はランダムな方向の期待値（10.7%）以下。層15 は座標 0 が 9.6% で、ほぼ密。座標 0 は層0・1・23 の u でも最大（51% / 37% / 58%）。`results/analysis_coord0.json`。

推定:
- 編集の効果は、「繰り返しに入るのを遅らせ、思考を終えて答えるまで進ませる」ことにあると見える（繰り返しの開始位置が遅くなり、思考を閉じる割合が上がる）。ただし、閉じた後の誤答も増えている（方法B で 95 件）。
- 方法A の学習が見つけているのは、方向ではなく、強さと列の重みの調整にとどまる可能性が高い。

### 3.13 論文の式を取り入れた編集の変更と、勾配プローブ（Issue #28・#27）

依頼者の指示は、「論文で紹介されている数式に、改善できるところがあるのではないか。似た研究を調べ、どんな式の変更ができるかを試す」でした。現在の式は `W[:,S] ← W[:,S] − α·u(uᵀW[:,S])`（u は平均差から作った固定の単位方向、S は上位 k 列）です。2 人の独立した調査エージェントが先行研究を調べました（要約サイト経由で読んだものと概要だけのものが混在し、式の書き写しは二次情報です）。同じ型の編集を Qwen3.5-0.8B や混合型のモデルで調べた論文は、見つかりませんでした。

**現在の式との違い（事実）**
- ROME・MEMIT・AlphaEdit は、書き込む方向ではなく**読み取り側のベクトル**を、入力の共分散 C で決める。私たちは「上位 k 列を選ぶ」ので、これは粗い近似にあたる。
- LEACE は、読み取りを共分散で白色化した斜め射影。refusal 方向の重み直交化（Arditi ら）は α=1 だが、全層・全位置・残差に書く全行列から取り除く。活性を足す手法は、down_proj にバイアスがないため、重みでは近似的にしか書けない。

**試した変更**（層 15+19、ρ は中心と同じ。設定選択用 128 問 × 2 回、16k、シード 2。中心は同じ条件の再評価 43.0%。差は問題単位の対応クラスタ・ブートストラップ）

| 変更 | 正答率 | 中心との差（95% 区間） |
|---|---|---|
| 座標 0 の行を除く（残りで ρ をそろえる） | 43.8% | +0.8（−3.9〜+5.5） |
| 座標 0 の行だけ（ρ は中心の 31%・55%） | 16.8% | −26.2（−33.2〜−19.1） |
| 共分散の読み取りベクトル（LDA 型、全列） | 43.0% | 0.0（−5.1〜+5.1） |
| 同、ρ を中心の 60% に下げる | 22.3% | −20.7（−27.3〜−14.1） |
| 斜め射影の読み取り（LEACE 型） | 7.8% | −35.2（−42.6〜−27.7） |
| u を正常な出力の平均方向に直交化 | 39.5% | −3.5（−8.2〜+0.8） |

事前に決めた「改善」の基準（+5 pt 以上で区間の下限が 0 超）を満たす変更は、ありませんでした。評価は 6 本、すべて探索的です（最終確認用の 256 問は使い切っています）。

事実:
- 座標 0 を除いても、効果は中心と同じ水準で残る。効果を担っているのは座標 0 以外の行で、座標 0 に絞る設計に利点はない（行を絞った編集 #26 は、この結果をもって実行しない）。
- LDA 型は、中心と同じ ρ では同じ正答率だが、繰り返しで打ち切られる割合は 17.6% から 39.8% に増えた。ρ を 60% に下げると 22.3%。参考（厳密な対照ではない）として、中心の式で強さだけを下げたとき、α4（ρ は約 67%）で 40.2%、α4.5（約 75%）で 44.1%（シード 0）。
- 斜め射影は無編集（13.3%）より悪かった。CPU の診断（教師強制の統計）では「弱い中心型の編集」に見え、悪化の原因は特定できていない。

推定: 効果の大きさは、乱れの小ささ（CPU の事前確認で LDA 型は 18〜37 倍の利得）ではなく、ループ文脈で u 方向の出力を強く押す強さで決まっているように見える。教師強制の統計から作る指標（Fisher 比など）は、編集後の生成の優劣を予測しなかった。

**勾配プローブ（#27）** 方法A の拡張（ランダムな初期方向から報酬だけで方向を学ぶ学習、約 4.5 GPU 時間 × 4）は、独立したレビューで「決め手になる結果が出ない」とされ、約 0.5 GPU 時間の勾配プローブを先に行いました。初期の編集済みモデルで、保存済みの標本（正誤が混ざる 105 問のうち、重ならない 2 組。各約 64 本）から RLOO の勾配行列を計算し、2 分割で比べた結果、事前に決めた通過の基準（出力側の特異ベクトルの 2 分割間コサイン 0.5 以上、既知の方向の割合 0.05 以上）を層 15・19 とも満たしませんでした（コサイン 0.01〜0.13、割合 0.0005〜0.0037、ランダム水準 0.0029）。列側の特異ベクトルは再現した（0.7〜0.99）。**報酬の一次の勾配は、この規模では方向について再現する情報を持たない**ので、学習は行っていません。方法A で u がほとんど動かなかった（#10）ことと整合します。

### 3.14 LLM 以外（CNN など）への適用の見通し

編集の式は、LLM 専用ではありません。畳み込み層も、`出力チャンネル × (入力チャンネル × カーネル)` の行列として同じ形で扱えます。画像分類器の重みをランク1で書き換える先行研究もあります（Santurkar ら「Editing a classifier by rewriting its prediction rules」、NeurIPS 2021。ある層の重みを書き換えて、VGG16 で「雪」の概念を「アスファルト」に対応させた。背景のような偽の手がかりを無視させる用途も示している）。偽の相関に対する重み 1 個の編集（arXiv 2501.14182）や、表現から線形に概念を消す LEACE（arXiv 2306.03819）もあります。

このリポジトリの結果が、そのまま CNN に当てはまるかは、**未検証**です。違いは次のとおりです（推定）。
- 直した失敗の種類: 「同じ文を繰り返し続ける」失敗は、自分の出力を入力に戻す LLM の仕組みから起きる。1 回の計算で答える CNN の対応物は、背景への依存、特定の集団での誤り、などになる。
- 方向 u の意味: Transformer には全層で共有する残差の空間があるが、CNN にはない。BatchNorm と ReLU を挟むので、「成分を取り除く」効果がそのままは伝わらない。
- 列の選び方が効くかどうか: 「どの列を選ぶか」が効く理由は、ニューロンごとに活性が疎な MLP の性質に依存している可能性がある。

CNN は、手法の優劣の検証には向いています。評価が 1 回の計算で済み、数秒で終わるので、探索・対照・効率化の手法を、多数の繰り返しで確かめられます。

### 3.15 重みを変えない代替との比較（Issue #30・#31、すべて探索的）

リポジトリの目標は「研究として、より適した手法を見つけること」です。そこで、編集が足しているものを測るために、重みを変えない方法を同じ問題で測りました。きっかけは、基底モデルの 13.3% が、Qwen3.5-0.8B のモデルカードの既定（非思考モード）ではなく、思考を強制した条件の値だったことです。モデルカードは、0.8B は思考がループしやすいと書いています。元ブログの +27〜35 pt は、この条件の基底に対する差です。

**測った重みを変えない方法**
- 非思考モード（思考を使わない）。サンプラーは、モデルカードの値（温度 1.0、top_p 1.0、top_k 20、presence 2.0）と、掃引した 4 設定。

**非思考の多数決（Issue #31 D）**

**温度を下げるだけで、ぶれは消えるか（Issue #32 段階 0、重みを使わない）**

## 9. 用語

### 元の資料にある用語

- **p50c**: 元リポジトリで、編集を作った実行の呼称です。本文では「公開編集」と書きました。
- **α、u、ランク1**: 編集の式に出てくる強さ、方向、構造の呼び方です。
- **DecisionBench、medium、hard**: Jev-Omni の評価データとその難易度の名前です。
- **noul、choice、score**: DecisionBench の質問型の名前です。noul は Yes/No、choice は選択肢から選ぶもの、score は段階を答えるものです。
- **micro、state-macro、ECE**: 公開値で使われている指標の名前です。state-macro は、状況ごとの正答率の平均です。

### 本検証で付けた呼称

- **基底モデル**: 編集する前のモデル。
- **公開編集**: 元リポジトリが公開している編集済みの重み。
- **自前編集**: Claude が 3.2 節の手順で作った編集。
- **旧方向／対比方向**: 自前編集の方向の作り方 2 種類（3.2 節）。
- **繰り返しの文脈／進んでいる文脈**: 3.2 節で方向を求めるために使った 2 種類の文脈（元資料の英語では repetitive / productive）。
- **繰り返しで終わった応答**: 打ち切られた応答のうち、末尾が同じ内容の繰り返しになっているもの。判定は `scripts/grade.py` の `loop_signals` です。
- **思考を閉じた割合**: 思考を閉じるタグに到達した応答の割合です。Qwen は `</think>`、Gemma 4 は `<channel|>` です。
- **完走して boxed のある答え**: 思考を閉じ、finish が stop で、回答部に `\boxed{}` がある応答。ラベルなしの選択の指標。
- **ρ（相対変化）**: ‖ΔW‖_F / ‖W‖_F。編集の大きさ。
- **ヌル対照**: ノルムを合わせたランダムな直交方向で、同じ式の編集をしたモデル。
- **方法A／方法B**: 正答率を目的にした、方策勾配 + AdamW による学習／ベイズ最適化による探索（3.9 節）。
- **ラベルなし選択**: 正解ラベルを使わない指標（完走して boxed のある答えの割合）で選んだ編集（3.10 節）。
- **最良との差**: 選んだ編集の正答率と、プール内の最良の正答率の差（旧称「後悔」）。
- **Holm 補正／問題単位のクラスタ・ブートストラップ**: 事前登録した、多重比較の補正と、問題を単位とした再標本化による区間・p 値の計算（3.11 節）。
- **方向探索用／設定選択用／検証用／最終確認用の問題**: 方向を求めた 256 問（`data/practice_find.jsonl`）、候補を選んだ 128 問（`data/practice_select128.jsonl`）、その残りの 128 問（`data/practice_select_rest128.jsonl`）、最後に測る新しい 256 問（`data/final_fresh.jsonl`）。
- **組み立て方 v1 / v2**: Jev-Omni の質問型から選択肢を作る規則（`scripts/eval_jev.py` の `--fmt`）。
